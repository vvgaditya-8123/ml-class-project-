# Executive Summary: Technical Audit of Newspaper Reading / OCR Module

**Project:** ML Class Project — Newspaper Reading & Layout OCR Pipeline  
**Evaluator Reference:** Deep Technical Audit & Generalisation Analysis  
**Auditor:** Senior ML Systems Engineer, Computer Vision Researcher, QA Lead  
**Audit Date:** November 6, 2026  
**Status:** **CRITICAL ARCHITECTURAL REBUILD REQUIRED**  

---

## 1. The Core Problem
The project owner observed that while the system appeared to achieve $> 98\%$ accuracy during development, it **completely fails on genuinely unseen newspaper scans or pages from different publishers**. The owner suspected that the dataset of ~20,000 character images was too small or that feature selection was weak.

**Verdict:** The hypothesis of "insufficient dataset size" is incorrect. The system fails because it uses an **isolated 36-class character classifier forced to act as a document reader**, a **layout model trained to imitate arbitrary geometric if-else rules with zero semantic understanding**, and **hardcoded fallback text that fabricates output while hiding failures from developers and users**.

## 2. Key Findings Matrix

| Component | Documented Claim | Verified Reality in Source Code & Runtime | Severity |
|---|---|---|---|
| **OCR Architecture** | 98.81% accuracy on 36 alphanumeric classes | Recognizes only `0-9` and uppercase `A-Z`. Contains **zero lowercase letters and zero punctuation**. Transcribes real newspaper body text as 100% unreadable character salad (e.g. `"LHXR HE HNHLUAMAEW FE HEHKMEEMHE..."`). Training crops are completely missing from the repository. | **CRITICAL** |
| **Layout Detection** | Random Forest with 99.80% accuracy on 188 pages | Model is trained on only 80 pages using **pseudo-labels generated by the exact same geometric rules the model is given**. Region-level split leaks same-page features. Hardcoded pixel thresholds (`bh >= 35`) cause high-resolution pages to shatter into 123 false "articles". | **CRITICAL** |
| **Output Integrity** | Hierarchical headline-to-article association | When OCR produces empty text, the system **silently injects a canned placeholder paragraph** (`"[Article X text under ...] Detailed investigative coverage continues..."`). In our 4-page audit, **74.8% of all articles (175/234) were fabricated placeholders**. | **CRITICAL** |
| **User Interface** | Real-time confidence metrics in desktop GUI | GUI displays the Random Forest's layout probability (e.g. `100.0%`) as the **OCR transcription confidence**, misleading users into believing unreadable text is perfectly recognized. Status bar string is hardcoded marketing text. | **HIGH** |
| **Test Suite** | 100% automated test pass rate (4/4 tests pass) | Tests pass deceptively: character tests are guarded by non-existent folder checks and silently skipped; end-to-end tests assert `len > 0`, which the canned placeholder text always satisfies. | **CRITICAL** |
| **OCR 3 Prototype** | Production-ready alternative OCR engine | **Non-functional prototype**: disconnected from GUI, core dependency (`paddle`) is not installed, preprocessing is computed but bypassed, CRNN backbone freezes uninitialized random weights, and benchmark tables are hardcoded mock dictionaries. | **CRITICAL** |

## 4. Top Three Immediate Actions for the Project Team

1. **Purge Synthetic Placeholders & Decouple Confidence:** Remove lines 84–86 and 98–100 of `newspaper_reader.py` to stop outputting fake text. Update `gui.py` to display true OCR recognition confidence rather than layout probability.
2. **Replace CharCNN with Sequence OCR:** Discontinue the 36-class isolated character classifier. Install and integrate a pretrained line-level sequence OCR model (such as PaddleOCR PP-OCRv4 or Tesseract 5) that natively supports full lowercase and punctuation.
3. **Replace Heuristic Layout with Learned Document AI:** Decommission the contour-based Random Forest model. Deploy a pretrained document layout detector (YOLOv8-Doc or DBNet) with normalized coordinates to ensure invariance across scan DPIs.
